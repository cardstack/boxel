# ADR 020 remediation

Places where the code does not meet [ADR 020](../020-run-every-launched-browser-with-its-sandbox-on-and-a-current-chrome.md)
yet (ADR 001 §1.6).

`packages/realm-server/prerender/browser-manager.ts`:

- `BrowserManager.getBrowser` breaks §1.2. It pushes `--no-sandbox` and
  `--disable-setuid-sandbox` unconditionally, on the prerenderer that renders
  card HTML from any realm. Its comment gives two reasons. The V8 `--prof`
  diagnostic needs the renderer to write its log, which can gate the flag on
  `v8ProfEnabled()`. The other, that the task "runs only in a container where
  the sandbox can't initialize", names no mechanism and has not been tested:
  the image runs as the non-root `pptruser` and installs
  `google-chrome-stable`, which ships the setuid sandbox helper.

`packages/realm-test-harness/src/support-services.ts`:

- `launchStandbyBrowser` breaks §1.2. It passes `--no-sandbox` and
  `--disable-setuid-sandbox` unconditionally, including on macOS and on Linux
  runners that are not root.

`packages/realm-server/scripts/wait-for-host-standby.ts`:

- `launchBrowserWithRetry` breaks §1.2. It turns the sandbox off whenever `CI`
  or `PUPPETEER_DISABLE_SANDBOX` is `true`, and states no reason for the `CI`
  case.

`packages/realm-server/tests/secure-origin-policy-test.ts`:

- the `before` hook's `puppeteer.launch` breaks §1.2 with an unconditional
  `--no-sandbox` and `--disable-setuid-sandbox`, and breaks §1.5 with
  `--disable-features=IsolateOrigins,site-per-process`. Its comment names the
  behaviour it needs (the framed credential fields in the page's own process)
  but not why no narrower flag gives it.

bundled Chromium 149.0.7827.55, below the floor of 156.0.8078.79:

- `packages/boxel-cli/src/lib/test-engine.ts` (`runQunitInBrowser`)
- `packages/software-factory/src/screenshot-execution.ts` (`captureHtmlScreenshot`)

`packages/boxel-cli/package.json`:

- the `@playwright/test` pin (`catalog:`, resolving to 1.61.0) breaks §1.3. The
  published `boxel test` cannot assume an installed Chrome, and the Chromium
  this version bundles is below the floor.

These launches break §1.5: each relaxes certificate validation for the whole
session without gating it on a loopback origin:

- `packages/ai-assistant-evals/playwright.config.ts` (`--ignore-certificate-errors`
  and `ignoreHTTPSErrors`, while `EVAL_HOST_URL` can name any host)
- `packages/ai-assistant-evals/assistant-eval.spec.ts` (`ignoreHTTPSErrors` on
  its own context)
- `packages/matrix/playwright.config.ts` (`--ignore-certificate-errors` and
  `ignoreHTTPSErrors`, for `localhost` and for `published.realm`, which the
  same launch maps to loopback, but with no gate on either)
- `packages/matrix/tests/secure-window-keys.spec.ts` (`ignoreHTTPSErrors` on
  its own context)
- `packages/host/testem.js`
- `packages/host/testem-live.js`
