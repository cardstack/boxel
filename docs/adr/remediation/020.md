# ADR 020 remediation

Places where the code does not meet
[ADR 020](../020-push-realm-changes-as-cacheable-http-invalidations-filtered-by-policy.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

`packages/runtime-common/event-feed.ts`:

- `RealmEventFeed#pathOf` skips every path with an extension, so a change to
  a module a visitor's page loads is never announced. Breaks §1.1.
- No reset is announced when the policy card changes, or when a linked card a
  grant reads changes. Breaks §1.2.
- The feed covers the whole realm; it has no subscriptions to an operation's
  results, and no per-subscription URL or window. Breaks §1.8.

`packages/runtime-common/realm.ts`:

- No response carries `Boxel-Feed-Position`: neither reads nor operation
  responses, and an atomic batch is not given a contiguous range. Breaks §1.3.
- Streams are not capped per realm and process. Breaks §1.4.
- A card's revision is its ETag alone: it doesn't change with the policy or
  permissions, and a card that links across realms has none. Breaks §1.5.
- Grants can't be marked private to keep their reads out of shared caches.
  Breaks §1.5.

`packages/runtime-common/anonymous-admission.ts`:

- Counts a signed-out read at the current revision (`?rev=`) against the
  realm's anonymous rate limit like any other read. Breaks §1.5.

`packages/host/app/services/event-feed.ts`:

- Opens one connection per realm rather than one per site through the
  boundary, and never closes a realm's feed when nothing watches it. Breaks
  §1.6.
- Treats a reset as "re-read everything", relayed as a full index event,
  rather than revalidating what it holds with conditional reads. The relay is
  spread over the time the realm sizes to its audience. Breaks §1.3.
- Opens the feed from the latest position, not from the earliest position of
  what the page read. Breaks §1.3.
- Ignores the `types` an event names, so every change still re-runs every
  live search. Using them needs the realm-relative keys turned into the keys
  the live-search gate compares, through the site's alias. Breaks §1.1.
- Honours a refresh request from any realm the page watches, and offers it to
  apps as a cancelable `window` event rather than through the card context.
  Breaks §1.7.
