# ADR 020 remediation

Places where the code does not meet
[ADR 020](../020-push-public-realm-changes-as-cacheable-http-invalidations.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

`packages/runtime-common/public-realm-events.ts`:

- `PublicRealmFeed` keeps its sequence in the memory of the process that
  serves the realm, so realm-server replicas each hold a separate sequence,
  and a change written through one replica never reaches a subscriber on
  another. Breaks §1.1 and §1.3.

`packages/runtime-common/realm.ts`:

- `cardJsonCacheControl` answers `public` only when the whole realm is
  world-readable, so a signed-out read a policy grant admits is `private`
  and no shared cache can serve it. Breaks §1.5.
- No card read can be addressed by revision. Breaks §1.5.

`packages/host/app/services/public-realm-events.ts`:

- Opens one stream per realm in each tab, rather than one connection per
  browser shared between its tabs. Breaks §1.6.
- Re-reads a changed card as soon as the event arrives, with no random
  delay. Departs from §1.5's SHOULD.
