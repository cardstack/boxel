# ADR 030 remediation

Places where the code does not meet [ADR 030](../030-batch-ai-only-when-an-automation-opts-in-end-the-run-while-it-waits-and-bill-every-batch.md)
yet (ADR 001 §1.6).

- `packages/runtime-common/automation-admission.ts` breaks §1.5. Admission lets a batch's follow-up run while its automation is paused, and checks a held follow-up's identity for revoked sessions since the submitting run started, not since the resume.
- `packages/runtime-common/automations.ts` breaks §1.5. A pause cancels the automation's pending run and its running one, a follow-up among them.
- `packages/runtime-common/ai-batch-follow-ups.ts` breaks §1.5. A follow-up a pause held starts after the resume acting as the submitting run's identity, not as the person who resumed.
- `packages/runtime-common/ai-batch-follow-ups.ts` breaks §1.2. A follow-up starts only at its batch's deadline: nothing starts it when the batch reaches a final state earlier, neither OpenRouter's completion webhook nor the minute tick's check of open batches.
- `packages/runtime-common/tasks/run-automation.ts` breaks §1.3. A follow-up's script is given no batch to read, so the follow-up neither uses the batch's results nor sends its requests at the normal price when the batch missed its deadline.
- `packages/runtime-common/automation-runs.ts` breaks §1.5. A canceled follow-up keeps its row's slot, so creating the batch's follow-up again returns the canceled run instead of a new one.
- `packages/runtime-common/automation-reconcile.ts` breaks §1.5. Reconcile ends a lost follow-up while its automation is paused instead of leaving it held.
- `packages/host/app/tools/run-realm-code.ts` breaks §1.1. A Preview's `realm.resolve.batch` is refused, since the batch path refuses a Preview's submit, instead of sending the requests at the normal price.
