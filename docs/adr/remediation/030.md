# ADR 030 remediation

Places where the code does not meet [ADR 030](../030-batch-ai-only-when-an-automation-opts-in-end-the-run-while-it-waits-and-bill-every-batch.md)
yet (ADR 001 §1.6).

- `packages/runtime-common/automation-admission.ts` breaks §1.5. Admission lets a batch's follow-up run while its automation is paused, and checks a held follow-up's identity for revoked sessions since the submitting run started, not since the resume.
- `packages/runtime-common/automations.ts` breaks §1.5. A pause cancels the automation's pending run and its running one, a follow-up among them, and a resume neither starts a follow-up the pause held nor makes it act as the person who resumed.
- `packages/runtime-common/automation-runs.ts` breaks §1.5. A canceled follow-up keeps its row's slot, so creating the batch's follow-up again returns the canceled run instead of a new one.
- `packages/runtime-common/automation-reconcile.ts` breaks §1.5. Reconcile ends a lost follow-up while its automation is paused instead of leaving it held, and re-enqueues a lost run without the input a follow-up carries.
