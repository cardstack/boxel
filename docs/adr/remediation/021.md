# ADR 021 remediation

Places where the code does not meet [ADR 021](../021-run-boxels-oauth-provider-in-the-realm-server-with-opaque-resource-bound-tokens.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

- `packages/realm-server/lib/oauth-provider/serve.ts`
  (`registerOAuthProviderRoutes`) registers the authorization server's
  discovery document, dynamic client registration, every step of the
  authorization code flow, and the token and revocation endpoints, but not
  the device endpoints, which breaks §1.1 and §1.7.
- `packages/realm-server/lib/oauth-provider/provider.ts`
  (`createOAuthProvider`) turns off the device flow, which breaks §1.1.
- `packages/realm-server/lib/secure-session.ts` revokes nothing after a
  password change whose device sweep couldn't be scheduled (the failure is
  logged and passed over), or after a reset whose email names no account, so
  the change leaves the user's OAuth grants live, which breaks §1.9. Their
  sessions are left the same way.
- `packages/secure-origin/src/shell/pages.js` has no device-code page, which
  breaks §1.1.
- `packages/runtime-common/tasks/indexer.ts` renders a card or module a
  `boxel:write` caller wrote with a realm-authority session for the realm's
  owner, which carries `realm-owner`, so code the caller chose runs beside a
  session that administers the realm, which breaks §1.5 and §1.6.
- `packages/runtime-common/realm.ts` (`#oauthPolicyChange`) never judges a
  module write, so an OAuth caller can change what a realm's policy admits by
  rewriting the RealmPolicy subclass its policy card adopts from (`rules` as a
  computed field), which breaks §1.6.
