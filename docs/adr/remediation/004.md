# ADR 004 remediation

Places where the code does not meet [ADR 004](../004-federate-realm-servers-each-paired-with-its-own-homeserver.md)
yet (ADR 001 §1.6).

- `packages/runtime-common/tasks/indexer.ts`,
  `packages/runtime-common/tasks/prerender-html.ts`, and
  `packages/runtime-common/worker.ts` (the `realmUsername` job argument)
  break §1.2. An indexing or prerender job names the user it runs as by
  localpart, which the worker qualifies with the configured server name. The
  sites that reduce an owner to that localpart are in scope too:
  - `Realm#getRealmOwnerUsername` in `packages/runtime-common/realm.ts`, and
    its callers there, in `packages/runtime-common/realm-index-updater.ts`
    and in `packages/realm-server/handlers/handle-reindex.ts`, rename an
    owner on another homeserver onto the paired one.
  - `packages/runtime-common/tasks/full-reindex.ts`,
    `packages/runtime-common/tasks/prerender-html-reconcile.ts` and
    `Realm#revisitPolicyCard` in `packages/runtime-common/realm.ts` refuse
    such an owner instead.
- `packages/runtime-common/realm.ts` (`getRealmOwnerUserId`, and the other
  `@realm/` prefix checks) breaks §1.2. It recognizes a realm's own account by
  localpart prefix, on any homeserver.
- `packages/realm-server/handlers/handle-publish-realm.ts` breaks §1.2. It
  matches the caller's localpart against the owner's published-space domain.
- `packages/realm-server/handlers/create-realm.ts` breaks §1.5. It builds
  every realm path from the owner's localpart.
- `packages/realm-server/lib/secure-window.ts` (`mayRead`) and
  `packages/realm-server/handlers/handle-publish-realm.ts`
  (`maybeApplyPublishedRealmOverride`) break §1.4. Each grants the `users`
  row to the user a session names without reading the `users` table, and a
  session signed with `REALM_SECRET_SEED` can name a user who has no row.
