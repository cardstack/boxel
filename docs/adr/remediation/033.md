# ADR 033 remediation

Places where the code does not meet [ADR 033](../033-map-host-urls-to-a-realm-by-its-identity-and-resolve-them-before-any-other-route.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

- `packages/realm-server/handlers/handle-publish-realm.ts` breaks §1.2: it
  copies a realm in order to serve it.
- `packages/base/default-templates/head.gts` breaks §1.4: it renders no
  canonical link, so a page the host app renders after it boots names none.
  `serve-index.ts` adds one only to the page it serves.
- `packages/realm-server/handlers/serve-index.ts` breaks §1.7: on a host URL
  it serves no default index card in full, because the prerenderer stores a
  placeholder for that card unless the realm's `realm.json` opts in.
- `packages/realm-server/routes.ts` breaks §1.4: no route serves a realm's
  sitemap.
- `packages/runtime-common/index-runner/prerender-html-visit.ts` breaks
  §1.8: it renders every realm's HTML against the realm's URL, whether or
  not the realm has host URLs.
- `packages/realm-server/handlers/handle-host-urls.ts` breaks §1.8: adding
  a realm's first host URL, changing its canonical host URL or removing its
  last host URL doesn't render the realm's HTML again.
- `packages/runtime-common/index-writer.ts` breaks §1.8: nothing records the
  URL that a row's stored HTML was rendered against.
- `packages/realm-server/lib/realm-host-urls-boundary.ts` breaks §1.8: it
  translates only responses on a host URL. It doesn't translate from the URL
  stored HTML was rendered against, and nothing names the realm's URL in
  place of the canonical host URL in a response on the realm's own URL.
