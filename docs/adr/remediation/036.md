# ADR 036 remediation

Places where the code does not meet [ADR 036](../036-route-dynamic-host-paths-through-two-declarative-route-forms-and-one-shared-resolver.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

- `packages/runtime-common/host-route-address.ts` (`hostRouteAddress`) has
  no caller: no `hrefTo` helper exists in `packages/base`. Links keep card
  URLs in the HTML visit and in the browser, nothing loads a linked card that
  isn't loaded, and no link that doesn't resolve is recorded in
  `prerendered_html.diagnostics`. Breaks §1.7 and §1.8.
- `packages/runtime-common/host-route-address.ts` (`hostRouteAddress`) gives
  a route's address when a literal or fixed route at the same level takes
  it, so the link opens the other route's card. Its header comment also shows
  a route name as a positional string (`{{hrefTo "people" person}}`), where
  §1.8 requires a named argument. Breaks §1.2 and §1.8.
- `packages/runtime-common/realm.ts` serves the validated route tree from
  `_host-routes`, but nothing reads it, and
  `packages/realm-server/handlers/serve-index.ts` puts `hostDynamicRoutes`
  only into a page served on a host URL. HTML visits and interact mode have
  no copy of the routes. Breaks §1.6.
- `packages/host/app/services/host-mode-service.ts`
  (`resolveDynamicRoutedPath`): in-app navigation to an alias serves the
  alias's card at the alias path, where a full page load answers 301 to the
  card's canonical address. Breaks §1.2.
- `packages/runtime-common/realm.ts`: a change to the realm's routes does not
  run the realm's HTML visits again, so stored links keep their old addresses.
  Breaks §1.7.
