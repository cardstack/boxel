# ADR 036 remediation

Places where the code does not meet [ADR 036](../036-route-dynamic-host-paths-through-two-declarative-route-forms-and-one-shared-resolver.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

- `packages/host/app/services/host-route-links.ts` (`routes`) gives a link a
  routed address only on a page served on a host URL, in an HTML visit, in
  interact mode and in code mode. In host submode, links keep card URLs.
  Breaks §1.7.
- `packages/host/app/services/host-route-links.ts` (`openRealmRoutes`)
  gives every link in interact mode and code mode the routes of the realm
  open there, not of the realm of the card the link renders in, which the
  `hrefTo` helper doesn't know in the app. A link in a card of another realm can then get
  an address an HTML visit of that card would not give it. Breaks §1.7.
- `packages/host/app/services/host-route-links.ts` (`routes`) can't tell a
  link the app renders from one the tab renders for its own index, which a
  tab does only in tests. While the tab renders for its index, a link in the
  app takes that index's routes. When the realm indexed is not the one open
  in the app, the link gets an address from the wrong realm's routes,
  or keeps its card URL, until it renders again. Breaks §1.7.
- `packages/host/app/services/host-route-links.ts` (`reportUnresolved`) only
  logs a link that doesn't resolve. Nothing records it in
  `prerendered_html.diagnostics`. Breaks §1.8.
- `packages/runtime-common/host-route-address.ts` (`hostRouteAddress`) gives
  a route's address when a literal or fixed route at the same level takes
  it, so the link opens the other route's card. Breaks §1.2.
- `packages/host/app/services/host-mode-service.ts`
  (`resolveDynamicRoutedPath`): in-app navigation to an alias serves the
  alias's card at the alias path, where a full page load answers 301 to the
  card's canonical address. Breaks §1.2.
- `packages/host/app/services/host-mode-service.ts` (`siteURL`, `sitePath`,
  `dynamicRoutesMount`), `packages/host/app/services/host-link-navigation.ts`
  (`findDestination`) and `packages/host/app/services/host-route-links.ts`
  (`linkedCards`, `routesFromPageConfig`) take a page served on a host URL to
  be at the realm's URL. A live render on such a page gives addresses on the
  realm's URL, and a link counts as inside the site only under the realm's
  URL. This holds while a site is served at the realm's URL, and breaks
  §1.7 and ADR 033 §1.5 once a host URL can differ from it.
- `packages/runtime-common/realm.ts`: a change to the realm's routes does not
  run the realm's HTML visits again, so stored links keep their old addresses.
  That includes a stored route tree that changes with no edit to realm.json:
  the first index that stores the tree for an index written before the index
  stored it, and an index that reads a route type whose read failed before.
  HTML visits that read the smaller tree keep card URLs for the routes it
  lacked. Breaks §1.7.
