# ADR 032 remediation

Places where the code does not meet [ADR 032](../032-define-the-card-contract-as-the-boundary-between-card-code-and-its-runtime.md)
yet (ADR 001 §1.6). Each entry names a file by its path from the repository
root, in backticks, and the requirement it breaks.

`packages/base/card-api.gts`:

- `searchable` (the `@field` option, its type, and its validation) breaks §1.3:
  an author can write it and nothing produces its semantics.
- `mode` and `submode` on `CardContext` break §1.4: host UI vocabulary in the
  interface every card sees.
- `Box` (exported from the module card authors import) breaks §1.5: a runtime
  reconciliation mechanism on the author-facing surface.
- `CardStore`'s diagnostic members (`queryLoadsInFlight`, `recentCardDocLoads`,
  `trackQueryLoad`, and their siblings) break §1.5.
- `capturesMeta`'s `deviceScaleFactor` breaks §1.4: a capture renderer's
  parameter as the author-facing meaning of a capture.
- `icon` typed `ComponentLike<{ Element: SVGSVGElement }>` breaks §1.4: the
  author declares a component from one icon package instead of a reference the
  environment resolves.
- `resolvesQueryFieldsEagerly`'s "absent means it does not" breaks §1.3: it
  inverts the author's `eager` default rather than reporting that the store
  cannot honor it.
- `RESERVED_FIELD_NAMES` covers two members of a larger provided instance
  surface, which breaks §1.8: a card can take a name the platform will want.
- `commandContext` (the pre-rename spelling kept beside `toolContext`) breaks
  §1.8: two names for one contract member, with no sunset.

`packages/runtime-common/formats.ts`:

- The `Format` union's `form` breaks §1.8: a format name no runtime implements.
- `metadata` in `fileDefFormats` but not in `formats` breaks §1.8:
  `isValidFormat('metadata')` is false while the file family accepts it.

`packages/runtime-common/search-doc-keys.ts` (`_title`, `_cardType`,
`_isCardInstanceFile`) and `packages/runtime-common/index-query-engine.ts`
(`generalSortFields`, `MATCH_RELEVANCE_SORT_KEY`):

- These break §1.4: index keys reachable from a query an author writes.
- `cardURL` in `generalSortFields` breaks §1.4: a sort by a URL that is not
  durable across deployments.

`packages/base/default-templates/file-def-edit.gts` and `FileDef.edit` in
`packages/base/card-api.gts`:

- A file def declares an `edit` template that `fileDefFormats` excludes, which
  breaks §1.3.

`packages/base/workspace.gts` and `packages/base/cards-grid.gts`:

- Filters on `_cardType` break §1.4: card-authored queries address the index's
  row layout.

`packages/base/default-templates/missing-template.gts`:

- It imports `switch-submode` from the host and passes `submode: 'code'`, which
  breaks §1.4: a card's default template drives the host's navigation.

`packages/base/command.gts` (`@field submode`):

- Host navigation vocabulary stored as card data breaks §1.4.

`packages/base/field-component.gts`, `packages/base/contains-many-component.gts`:

- `import type { Box } from './card-api'` breaks §1.5.

`packages/base/field-component.gts`, `packages/base/links-to-editor.gts`,
`packages/base/realm-config.gts`:

- Behavior that branches on "code submode" breaks §1.4.

`packages/host/app/components/search/constants.ts` (`by: '_title'`):

- Breaks §1.4: a synthetic index key as a UI-facing sort choice.

`eslint/ambient-clock-selectors.cjs` and `eslint/erasable-syntax-selectors.cjs`:

- Each is the only place its rule is stated, which breaks §1.6. Card Contract
  now states both rules; the rules' own messages still give a reason that does
  not apply to card code.

`eslint/data-test-selectors.cjs`:

- Its justification differs by build context, which breaks §1.4: whether
  `data-test-*` reaches a person is a rendering detail a card can currently
  depend on.
