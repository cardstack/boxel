# Remediation for ADR 032

Gaps in the code the ADR governs. Entries carried over from
[remediation/010.md](remediation/010.md) are marked _carried_; that file went
with the ADR it listed.

## §1.1 — the Loader must not evaluate a module

- `packages/runtime-common/loader.ts` — the whole file. `fetchModule` and
  `evaluateModuleInCurrentRealm` transpile a module to AMD and `eval` it in the
  page; `moduleCacheKey` and `trimModuleIdentifier` fold extension and alias
  spellings into one cache entry; `shimModule`, `moduleShims`, and `cloneLoader`
  are the shim registry and the Loader copies.
- `packages/runtime-common/amd-transpile/**` — exists to feed that `eval`.
- `packages/host/app/services/loader-service.ts` — constructs the only Loader
  the app has, and `publish` puts it on `globalThis`.
- `packages/runtime-common/bundled-module-loader.ts` — the `globalThis` slot a
  Loader publishes itself to.
- `packages/realm-server/tests/loader-dynamic-import-test.ts` — constructs a
  Loader and evaluates a module in Node.
- `packages/host/tests/unit/loader-test.ts`,
  `packages/host/tests/unit/{loader-concurrent-cycle-test,loader-consumed-modules-truncation-test,loader-fetch-failure-test,loader-icon-error-test,loader-mapping-change-test,loader-parallel-prefetch-test,loader-retry-test}.ts`
  — test the Loader itself.

## §1.2 — a module reaches the browser at its realm URL

- No import map is installed anywhere. Resolution is
  `packages/runtime-common/virtual-network.ts`'s `resolveImport`, a JS handler
  the Loader calls. _carried_: it rewrites the matched remainder of a prefix
  entry rather than resolving per the HTML algorithm; `addImportMap` accepts a
  bare specifier with no trailing `/`, which the HTML algorithm never matches; an
  unmapped bare specifier resolves to a fake `https://cardstack.com/base/` origin
  instead of failing.
- Bare specifiers reach realm code today as shims, not as URLs:
  `packages/host/app/lib/externals.ts` (`shimExternals`),
  `packages/host/app/lib/bundled-base.ts` (`shimBundledBase`),
  `packages/host/app/tools/index.ts` (`shimHostTools`, `shimHostToolModule`),
  and `packages/runtime-common/package-shim-handler.ts`. Each needs a URL the
  map can name.
- `packages/host/app/services/network.ts` (`configureVirtualNetwork`) — _carried_.
  The `@cardstack/boxel-icons/` entry appends `.js` to the remainder, so a
  specifier that already names an extension resolves to `icon.js.js`.
- `packages/runtime-common/package-shim-handler.ts` (`trimModuleIdentifier`) —
  _carried_. Shims are keyed by extension-folded identifiers.
- `packages/runtime-common/code-ref.ts`, `packages/host/app/tools/capture.ts`,
  `packages/host/app/lib/visual-capture.ts` — turn a module identifier into a URL
  by reaching the VirtualNetwork (`getVirtualNetwork`), which is how a card's
  module URL is recovered today.
- `packages/runtime-common/create-response.ts` — _carried_. Exposes
  `X-Boxel-Canonical-Path` in `Access-Control-Expose-Headers`; `realm.ts` still
  answers a module request with the module's canonical path in that header.

## §1.3 — no loader-only extensions

- `packages/runtime-common/loader.ts` — `getConsumedModules`,
  `getKnownConsumedModules`, `isModuleLoaded`, `loadedModuleKeys`,
  `moduleShims`, `moduleMap`: the module graph read out of the loader that is
  evaluating it.
- `packages/runtime-common/loader-plugin.ts` and
  `packages/host/lib/import-meta-loader-plugin.cjs` — rewrite a module's `fetch`
  and dynamic `import()` into `import.meta.loader`.
- `packages/base/{glimmer-index,fields/links-to/links-to,fields/deferred,fields/lazy-fields,fields/boxed,fields/case-insensitive}.gts`
  and `packages/experiments-realm/PosterBoard.gts` — read `import.meta.loader`.
- `packages/runtime-common/scoped-css.ts` (`maybeHandleScopedCSSRequest`) —
  answers an inline scoped-CSS module request inside the page's fetch layer.
- `packages/host/public/auth-service-worker.js` — injects the `Authorization`
  header for realm images, stylesheets, and the `_capture/` retry path, not for
  module requests.
- `packages/runtime-common/authorization-middleware.ts` — attaches the
  `Authorization` header in the host's fetch middleware, which is the layer a
  native `import()` cannot reach.
- `packages/host/app/lib/prerender-util.ts` (`transitiveModuleDeps`) and
  `packages/host/app/routes/module.ts` (`getConsumedModules`) — read dependency
  information from the Loader.

## §1.4 — the app never re-evaluates a module

- `packages/host/app/resources/file.ts` (`onRealmInvalidation`, `writeTask`),
  `packages/host/app/services/card-service.ts` (`saveSource`),
  `packages/host/app/routes/module.ts`, and
  `packages/host/app/tools/{evaluate-module,instantiate-card}.ts` (`run`) —
  discard the whole Loader for one code change.
- `packages/host/app/services/store.ts` (`rebuildForCodeChange`) — rebuilds every
  card instance in the store when a code change discards the Loader.
- `packages/host/app/routes/render.ts` (`#synchronizeLoaderEpoch`) and
  `packages/host/app/components/card-prerender.gts` — a warm prerender page
  discards its module map when the realm's epoch moves, instead of being retired
  or reloaded.
- `packages/runtime-common/index-runner.ts` and
  `packages/realm-server/tests/index-loader-reset-test.ts` — the predicate that
  decides when a prerender tab drops its modules. Under §1.4 it decides whether
  the tab may be reused at all.
- Nothing in the app tells someone that the cards on screen run a superseded
  revision. The realm's epoch is read to reset a Loader
  (`packages/host/app/resources/file.ts`), not to inform the person editing.
- `packages/runtime-common/helpers/const.ts` — `testRealmURL` is one constant, so
  every host test writes to the same module URLs in one page session and relies
  on `packages/host/tests/helpers/index.gts` calling `loaderService.resetLoader`
  in teardown to see new code for a path it already loaded.

## §1.5 — the preview jail

- No preview jail exists. `packages/host/app/components/operator-mode/code-submode/**`
  previews the module being edited by rendering a card instance from the app's
  own module graph (`playground-preview.gts` → `CardRenderer`), which is why
  editing a card has to discard the Loader.
- No URL scheme names a revision of a realm module, and no preview compile step
  rewrites a jailed subgraph's specifiers to those URLs.
- `packages/host/app/tools/evaluate-module.ts` and
  `packages/host/app/tools/instantiate-card.ts` verify code by discarding the
  Loader rather than by evaluating the revision they wrote in a jail.

## Tests that assume the Loader

- `packages/host/tests/helpers/index.gts` — constructs a Loader for a test realm
  (`new Loader(realm.__fetchForTesting, virtualNetwork.resolveImport, …)`) and
  calls `loaderService.resetLoader` in teardown, so every host test that loads a
  card goes through it.
- `packages/host/tests/unit/{index-query-engine-test,instance-filter-matcher-test,operation-lowering-test,searchable-option-test}.ts`
  — call `shimExternals` and construct a Loader.
- `packages/host/tests/unit/{runtime-dependency-tracker-test,virtual-network-reset-test}.ts`
  — construct a Loader.
