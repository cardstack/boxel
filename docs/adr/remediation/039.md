# ADR 039 remediation

Places where the code does not meet [ADR 039](../039-approve-an-automations-keys-when-it-is-switched-on-for-its-life-and-again-after-it-changes.md)
yet (ADR 001 §1.6).

- `packages/runtime-common/automation-index-hook.ts` (`syncAutomationsAfterIndex`) compares only the approvals already given, and the realm's full check after a pass is best-effort: `packages/runtime-common/realm.ts` (`followAutomationKeyApprovalsOnRequest`) answers the worker's request to check the automations' key approvals after a pass once the check has started, and holds the check only in the realm server's memory: `stopRealmServer` in `packages/realm-server/main.ts` doesn't wait for a realm's `incrementalIndexing()`, so a server stopped before the check commits drops it. `packages/runtime-common/tasks/indexer.ts` (`followAutomationKeyApprovalsInRealm`) sends the request once, and a refused, timed-out or failed request is logged with no retry. For a pass no realm awaits, nothing else checks, which breaks §1.6: an automation whose approvals all match again, or whose edit adds an operation needing a key no approval covers, waits for an approval landing or its next run's admission.
- `packages/runtime-common/automations.ts` (`followKeyApprovals`) moves an automation to _waiting for key approval_ without telling its payer, through the automation's own notice, that the automation waits and on whom, which breaks §1.4.
- `packages/runtime-common/automations.ts` (`waitForKeyApproval`) moves an automation to _waiting for key approval_ when the worker refuses one of its runs for a key approval it lacks, at admission or at a call, without sending the notices of §1.4: the worker can't check the automation, so its key-owner notices follow only at its next check in a realm server, which breaks §1.4.
- `packages/secure-origin/src/shell/keys/approval-batch.ts` (`ApprovalUse`) approves bindings only, for automations or interactive use, and writes no automation approval or version, which breaks §1.3.
- `packages/secure-origin/src/shell/keys/approve-page.gts` offers no approve mode for an automation's approvals, which breaks §1.3.
