# ADR 039 remediation

Places where the code does not meet [ADR 039](../039-approve-an-automations-keys-when-it-is-switched-on-for-its-life-and-again-after-it-changes.md)
yet (ADR 001 §1.6).

- `packages/runtime-common/automations.ts` (`AutomationState`) has no _waiting for key approval_ state, which breaks §1.1.
- `packages/runtime-common/automations.ts` (`switchOnAutomation`, `resumeAutomation`) starts the automation active without checking its approvals, asking for them or sending a notice, which breaks §1.1, §1.3 and §1.4.
- `packages/runtime-common/automations.ts` (`syncAutomationWithCard`) doesn't compare the automation's version with its approvals, which breaks §1.6.
- `packages/runtime-common/automations.ts` (`removeAutomation`) deletes only the automation's row, not its approvals, which breaks §1.2.
- `packages/runtime-common/automation-index-hook.ts` (`syncAutomationsAfterIndex`) syncs an automation only when its card is touched, not its script file, which breaks §1.6.
- `packages/runtime-common/automation-reconcile.ts` (`reconcileLostRun`) enqueues a lost run again for any automation that isn't paused, which breaks §1.1 for an automation waiting for key approval.
- `packages/runtime-common/automation-admission.ts` (`admitRunIdentity`) refuses a trigger's run only when the automation is paused, so a run enqueued before the automation began waiting still starts, which breaks §1.1.
- `packages/runtime-common/tasks/run-automation.ts` doesn't pass the version the attempt read to the realm's admission check, which breaks §1.7.
- `packages/realm-server/lib/key-bindings.ts` (`approveBindings`) records no automation approval and names no version, which breaks §1.2 and §1.3.
- `packages/realm-server/lib/key-bindings.ts` (`automationAdmission`) admits a run on any active binding approved for automations, with no automation approval or version check, which breaks §1.2 and §1.7. It admits Preview and Run now the same way, which breaks §1.7.
- `packages/realm-server/lib/key-binding-revocation.ts` ends bindings without moving the automations that use them to _waiting for key approval_, which breaks §1.4.
