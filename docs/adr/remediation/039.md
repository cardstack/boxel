# ADR 039 remediation

Places where the code does not meet [ADR 039](../039-approve-an-automations-keys-when-it-is-switched-on-for-its-life-and-again-after-it-changes.md)
yet (ADR 001 §1.6).

- `packages/realm-server/lib/key-bindings.ts` (`fillSlots`) fills a slot of an automation run's call from any active binding approved for automations, with no automation approval or version check, which breaks §1.2; only the run's admission checks the approval. It fills a Preview's and a Run now's slots the same way, which breaks §1.7.
- `packages/realm-server/lib/key-binding-revocation.ts` (`revokeBindingsIn`) moves the automations a revoked binding served to _waiting for key approval_, but sends no notice and, outside the owner's own revocation, no `automation` event, which breaks §1.4.
- `packages/runtime-common/automation-index-hook.ts` (`syncAutomationsAfterIndex`) moves an automation to _waiting for key approval_ when an edit stops an approval matching, but never back when an edit makes every approval match again, which breaks §1.5 and §1.6: the worker can't read a private realm's operation definitions, so the automation waits until an approval lands, a switch-on or a resume.
- `packages/runtime-common/automations.ts` (`followKeyApprovals`, `waitForKeyApproval`) moves an automation into and out of _waiting for key approval_ without sending the notices of §1.4.
- `packages/runtime-common/tasks/run-automation.ts` doesn't pass the card and script the attempt read to the realm's admission check; the realm compares the approvals with the card and script as it reads them, which can be newer than the attempt's, which breaks §1.7.
- `packages/secure-origin/src/shell/keys/approval-batch.ts` (`ApprovalUse`) approves bindings only, for automations or interactive use, and writes no automation approval or version, which breaks §1.3.
- `packages/secure-origin/src/shell/keys/approve-page.gts` offers no approve mode for an automation's approvals, which breaks §1.3.
- `packages/host/app/services/key-notices.ts` counts no automation-approval notice in the API Keys badge, which breaks §1.4.
- `packages/host/app/lib/key-notices.ts` reads no automation-approval notice, which breaks §1.4.
