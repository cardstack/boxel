# ADR 039 remediation

Places where the code does not meet [ADR 039](../039-approve-an-automations-keys-when-it-is-switched-on-for-its-life-and-again-after-it-changes.md)
yet (ADR 001 §1.6).

- `packages/realm-server/lib/automation-key-approval-records.ts` (`waitForKeyApprovalOfBindingsIn`) moves the automations a revoked, removed or moved binding served to _waiting for key approval_, but sends no notice, which breaks §1.4.
- `packages/runtime-common/automation-index-hook.ts` (`syncAutomationsAfterIndex`) compares only the approvals already given, and the realm's full check of a touched automation's approvals follows only the incremental passes the realm starts, which breaks §1.6 for an edit that a pass the realm didn't start is the first to index (a from-scratch pass, or an incremental pass the worker enqueues on its own, such as the prerender reconcile's, over a file changed while no realm server watched it): an automation whose approvals all match again, or whose edit adds an operation needing a key no approval covers, waits for an approval landing or its next run's admission.
- `packages/runtime-common/automations.ts` (`followKeyApprovals`, `waitForKeyApproval`) moves an automation into and out of _waiting for key approval_ without sending the notices of §1.4.
- `packages/secure-origin/src/shell/keys/approval-batch.ts` (`ApprovalUse`) approves bindings only, for automations or interactive use, and writes no automation approval or version, which breaks §1.3.
- `packages/secure-origin/src/shell/keys/approve-page.gts` offers no approve mode for an automation's approvals, which breaks §1.3.
- `packages/host/app/services/key-notices.ts` counts no automation-approval notice in the API Keys badge, which breaks §1.4.
- `packages/host/app/lib/key-notices.ts` reads no automation-approval notice, which breaks §1.4.
