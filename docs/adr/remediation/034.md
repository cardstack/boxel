# ADR 034 remediation

Places where the code does not meet
[ADR 034](../034-keep-each-realms-history-in-a-sha-256-git-repo-named-by-its-permanent-registry-id.md)
yet (ADR 001 §1.6).

The repos are still written and read in the SHA-1 object format:

- `packages/realm-historian/src/git-objects.ts`: `hashObject` names objects by
  their SHA-1, and `TreeEntry` and `treeBody` take 40-hex ids, which breaks
  §1.1.
- `packages/realm-historian/src/repo-format.ts`: `initRepo` creates a repo in
  the SHA-1 object format, and `updateMain` and `parseIncludesSuperseded` take
  40-hex ids, which breaks §1.1. `updateMain` also creates `refs/heads/main`
  against a 40-zero null id.
- `packages/realm-historian/src/reader.ts`: `REVISION_PATTERN` and
  `OBJECT_ID_PATTERN` accept at most 40 hex characters, so the reader refuses
  a full SHA-256 revision id and finds no object, which breaks §1.1.
- `packages/realm-historian/src/maintenance.ts`: the pass counts the objects
  `git prune -v` removes by matching 40-hex ids, so in a SHA-256 repo it
  counts none, which breaks §1.1.
- `packages/realm-historian/tests/repo-format-test.ts` expects 40-hex ids,
  which breaks §1.1.
- `packages/realm-historian/tests/git-objects-test.ts` expects git's SHA-1 id
  for a blob, which breaks §1.1.

Other gaps:

- `packages/realm-server/handlers/handle-delete-realm.ts` deletes a realm and
  leaves its repo, which breaks §1.1.
- `packages/realm-server/lib/realm-registry-backfill.ts`
  (`upsertBootstrapRealms` and `upsertSourceRealms`) inserts rows by URL
  alone, so a realm directory whose row has another URL gets a second row,
  which breaks §1.2.
- `packages/realm-historian/src/git-capabilities.ts` (`probeGit`) runs at
  startup but doesn't check that `git` supports the SHA-256 object format,
  which breaks §1.7.
