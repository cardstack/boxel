# ADR 027 remediation

Places where the code does not meet [ADR 027](../027-keep-an-automations-state-in-its-realm-and-commit-a-runs-writes-as-one-batch.md)
yet (ADR 001 §1.6).

`packages/runtime-common/realm.ts`:

- `createCard`, `patchCardInstance`, `removeCard` and `removeCardSource`
  don't stage a run's write, so a run's write through them is refused rather
  than staged (§1.2 asks that every write be staged). The card+source write,
  its octet-stream spelling, `_atomic` and the `_operations` write entries
  stage into the overlay. A run can't delete a file, through any route: an
  overlay row holds a file's bytes, with nothing to mark a staged delete.
- `getFileMeta` and the raw byte read that `fallbackHandle` serves break
  §1.3. A run reads the realm's version there, not the version it staged.
- `handleOperations` resolves a run's entries, and runs its `read` and
  `readSource` entries, against the realm and its index rather than the
  overlay (§1.3). A declared operation on a card the run created resolves
  against no type, and a read entry answers the realm's version.
