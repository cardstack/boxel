# ADR 026 remediation

Places where the code does not meet [ADR 026](../026-give-an-automation-run-a-token-for-its-realm-alone-and-act-as-a-person-through-handleautomation.md)
yet (ADR 001 §1.6).

`packages/runtime-common/realm.ts` (`handlePipeline`):

- breaks §1.2. It runs a batch under the session of the user it runs as, not
  a token for one run and one realm.
- breaks §1.3. It checks no run row, time limit or cap.
- breaks §1.4. It does not refuse an operation that the automation does not
  declare, and it marks `callApi` entries `callApiMode: 'pipeline'`.
- breaks §1.5. It authorizes a batch as that user's request would be, which
  admits a writer through a policy grant, and it never checks direct write.

`packages/realm-server/lib/key-bindings.ts` (`pipelineAdmission`) breaks
§1.4. It checks that the type defines the operation, not that the automation
declares it, and it checks bindings with `mode: 'pipeline'`.

`packages/runtime-common/card-operations/call-api.ts` (`CallApiMode`) breaks
§1.4. It has no `automation` mode.

`packages/realm-server/lib/key-uses.ts` (`recordKeyUses`) breaks §1.4. A
`key_uses` row has no run id, and the table's mode check allows only
`interactive` and `pipeline`.
